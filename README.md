# 病历结构化项目 · 模拟数据包(50 份)

> ⚠️ **重要声明:本仓库数据 100% 为程序随机生成的虚构内容**——姓名、住院号、年龄均为编造,不包含任何真实病人信息,可安全用于学习、演示与测试。

本项目演示如何将非结构化的中文出院小结批量清洗为结构化表格,并配套"提取结果 vs 金标准"的一键校验,面向医学文本结构化与数据质检方向的学习与演示。

---

## 一、这个文件夹里有什么

```
病历结构化项目/
├── data/                        ← 50 份模拟出院小结(patient_001.txt ~ patient_050.txt)
├── clean_patient_records.py     ← 清洗脚本:把 data/ 一次性清洗成结构化表格
├── gold_standard.csv            ← 标准答案(每份的"真值"),跑完程序后用来对准确率
├── generate_data.py             ← 数据生成器(改 N 可扩量,改 SEED 可换一批)
├── output/                      ← 清洗脚本的输出(4 张表 + 1 个 Excel)
├── requirements.txt             ← 运行依赖(pandas / openpyxl)
├── verify_against_gold.py       ← 一键验证:提取结果 vs 金标准,可复查下方分数
├── tests/test_regressions.py    ← 回归测试:检查修复过的问题是否再次出现
└── README.md                    ← 本说明
```

## 二、清洗脚本:从非结构化 txt 到结构化表格

`clean_patient_records.py` 把 50 份出院小结清洗成 5 个结果文件(全部输出到 `output/`):

| 输出文件 | 内容 |
|---|---|
| `病历结构化_宽表.csv` | 一行一个病人:基本信息、住院天数、主诉、诊断、合并症、用药(、连接) |
| `病历结构化_合并症长表.csv` | 合并症拆开,一行一条(方便统计频次,如"2型糖尿病 12 人") |
| `病历结构化_用药长表.csv` | 用药拆成 (药名, 剂量, 频次) 三列 |
| `数据质量报告.csv` | 逐人标记质量问题:缺字段 / 日期缺失 / 部分用药缺剂量等 |
| `病历结构化结果.xlsx` | 以上 4 张表合成一个 Excel,多 sheet 分页 |

**运行方式**(在项目目录下):

```bash
pip install -r requirements.txt   # 安装依赖(pandas / openpyxl)
python clean_patient_records.py   # 运行清洗脚本
python verify_against_gold.py     # (可选)一键验证:提取 vs 金标准,复查下方分数
python -m unittest discover -s tests -v  # 回归测试,只写临时目录
```

路径基于脚本自身解析(读旁边的 `data/`、写旁边的 `output/`),clone 下来装好依赖即可直接跑,不需要改代码。实测环境:Python 3.14.6 + pandas 3.0.3 + openpyxl 3.1.5(Python 3.10+ 环境应也可运行)。

**输入 → 输出示例**(取自仓库内 `data/patient_001.txt`):

```text
姓名:李建国  性别:女  年龄:39岁  住院号:ZY100037
入院日期:2026-10-07  出院日期:2026-10-11

出院带药:
1. 头孢呋辛酯片 0.25g 每日两次
2. 盐酸氨溴索片 30mg 每日三次
3. 盐酸二甲双胍片 0.5g 每日两次
```

运行 `python clean_patient_records.py` 后,`output/病历结构化_宽表.csv` 中该病人的一行(节选):

| 患者ID | 姓名(脱敏) | 性别 | 年龄 | 住院天数 | 出院诊断 | 合并症 | 用药数量 | 质量问题 |
|---|---|---|---|---|---|---|---|---|
| ZY100037 | 李** | 女 | 39 | 4 | 社区获得性肺炎、2型糖尿病 | 2型糖尿病 | 3 | 无 |

`output/病历结构化_用药长表.csv` 则将每种药拆成一行:

| 患者ID | 药名 | 剂量 | 频次 |
|---|---|---|---|
| ZY100037 | 头孢呋辛酯片 | 0.25g | 每日两次 |
| ZY100037 | 盐酸氨溴索片 | 30mg | 每日三次 |
| ZY100037 | 盐酸二甲双胍片 | 0.5g | 每日两次 |

**清洗前 vs 清洗后**——脚本针对本批数据中出现过的脏点(见第四节)做了处理:3 种表头格式、4 种日期写法(含 `2026年3月25日`)、编号/无编号/带"考虑"的诊断、藏在"出院医嘱"话术里的药品、"1 吸"这类特殊剂量单位、一行挤多种药(用`、`连接)、数字与中文间的怪空格(`2 型糖尿病`→`2型糖尿病`)。输出中**姓名一律脱敏**(`李建国`→`李**`),患者用住院号标识。

**与标准答案的对拍结果**(50 份全量,金标准见第五节):主要诊断 50/50、药物集合 50/50、合并症集合 50/50。字段完整率 100%(指住院号/日期/诊断/用药均非空,不表示内容临床正确);质量问题 6/50(均为原始数据本身缺剂量,非提取遗漏);住院天数中位 7 天。

验证脚本先检查标准答案的必需列、非空且唯一的文件名、非空主要诊断、病例与答案文件名集合完全一致,然后比较内容。缺文件、多文件、重复答案、空数据或内容不一致均以退出码 1 结束;完整通过返回 0。样本数可以变化,不会把 50 写死为程序要求。空合并症与空药物集合允许作为答案。

三项对拍只验证主要诊断名称、合并症集合和药名集合,不覆盖全部诊断、剂量、频次、日期及诊断确定性。回归测试另行检查指定的剂量与质量报告例子,不等于这些字段在所有文本中都正确。

## 三、每份病历里有什么(可提取的字段)

每份出院小结是一段**非结构化中文文本**,内含 4 类信息:

| 信息 | 出现位置 | 示例 |
|---|---|---|
| 基本信息 | 姓名/性别/年龄/住院号 | `姓名:杨晓东 性别:男 年龄:70岁 住院号:ZY100111` |
| 诊断 | 出院诊断 / 诊断区 | `1. 高血压病 2 级(很高危)` |
| 合并症 | 当前程序从文本的“既往有……”片段提取，不融合出院诊断中的条目 | `既往有2 型糖尿病病史10年。` |
| 用药 | 出院带药 / 带药区 | `苯磺酸氨氯地平片 5mg 每日一次` |

## 四、这批数据埋了哪些"脏点"(做清洗/质检的素材)

真实病历不会整整齐齐,所以脚本按比例埋入以下问题,**提取程序必须处理它们**:

| 脏点类型 | 设计比例 | 样子 |
|---|---|---|
| 诊断带"考虑"(未确诊口吻) | ~10% | `出院诊断:考虑 社区获得性肺炎、2 型糖尿病` |
| 诊断无编号(顿号连排) | ~15% | `出院诊断:高血压病 2 级(很高危)、脑梗死` |
| 无合并症(既往史正常) | ~6% | 出院诊断只有 1 条 |
| 带药缺编号 | ~10% | `苯磺酸氨氯地平片 5mg 每日一次`(无"1."前缀) |
| 带药缺剂量 | ~12% | `阿司匹林肠溶片 每日一次` |
| 多药挤成一行 | ~10% | 所有药用"、"连成一行,无换行 |
| 日期格式变体 | ~24% | `2026-03-23` / `2026.10.10` / `2026年2月19日` |
| 同一份日期格式混用 | ~6% | 入院 `2026-03-23`,出院 `2026.03.28` |
| 三种版式混排 | 随机 | 字段顺序、栏目叫法(带药/出院医嘱/出院带药)不完全一致 |

## 五、标准答案与质量验证(gold_standard.csv)

运行提取程序后,将程序输出与标准答案对比:

```
file                主要诊断            合并症                    药物
patient_001.txt     社区获得性肺炎      2 型糖尿病                头孢呋辛酯片；盐酸氨溴索片；盐酸二甲双胍片
```

用三件事做质量验证(对拍结果见第二节):
1. **字段缺失率**——50 份里每个字段空了多少;
2. **提取准确率**——程序提取 vs 标准答案,一致的比例(注意:程序输出"药物 5 种 vs 标准 5 种"时,要先做名称归一化再比对);
3. **抽样人工核对**——抽 5 份,肉眼对照文本与提取结果,记录对/错。

## 六、自定义数据规模(扩量或换批)

```bash
python generate_data.py --output-dir ../new-batch  # 在独立的新批次目录生成
```

- `N`(份数):如改 `N = 100` → 生成 100 份(文件名自动延续 patient_001…)
- `SEED`(随机种子):更换 seed 可生成另一批数据;同一 seed 每次结果完全一致,保证可复现

`--output-dir` 指定的批次目录会同时包含 `data/` 和 `gold_standard.csv`。若该目录已有标准答案或非空 `data/`,程序在写入前拒绝运行,不会覆盖文件,也不会把缩量后的新数据与旧病例混在一起。每次换批、扩量或缩量请换一个新的批次目录。不传此参数时使用生成器所在目录;本仓库已有固定样本,因此直接运行会提示拒绝覆盖。

要处理新批次,将 `clean_patient_records.py`、`verify_against_gold.py` 复制到新批次目录,在该目录运行这两个脚本。结果写入新批次的 `output/`。仓库原有 50 份旧版测试样本保持不变。

## 七、数据怎么来的

> "50 份模拟出院小结由数据生成脚本(本仓库 `generate_data.py`)产出:内置 15 种主诊断、12 种合并症、35 种药品名称(去重后)的字典库,按临床书写习惯模板化拼接;随机埋入缺失合并症、诊断带'考虑'、日期格式不一、剂量缺失等噪声,模拟真实文本的不规整性,用于测试提取程序的鲁棒性。"

> **开发方式声明**:本项目用于学习医学文本结构化与数据质检。作者主导项目设计、数据方案与质量验证,包括:提出项目需求(将模拟出院小结清洗为结构化表格)、制定数据使用约束(仅用模拟数据、输出姓名脱敏)、运行验收与金标准对拍结果核对(50/50)、推动并确认缺陷修复(如合并症在"病史"处截断导致的漏病)。代码在 AI 编程工具的辅助下编写与迭代。

## 八、已知限制(不做过度承诺)

- **诊断确定性未区分**:原始文本中带"考虑"(疑似口吻)与明确诊断被同样处理,未保留"疑似/确诊"状态;
- **否认/未记录未区分**:无合并症的统一返回空,未区分"明确否认既往史"与"病历未记录既往史";
- **用药信息**:仅提取药名/剂量/频次三字段,剂量与频次的临床合理性未校验;个别病历原始文本本身缺剂量;
- **规则范围**:医嘱过滤使用固定词表,合并症遇“否认”截断,均不代表已完整理解复杂叙述;
- **部分日期缺失**:当前日期解析以成对日期为主,只写入院或出院日期时可能无法保留已有日期,并统一标为日期无效;暂未逐个日期区分缺失原因;
- 以上限制不影响本批数据的字段提取与金标准对拍,但真实临床文本语义更复杂,迁移到真实数据前需重新评估。
